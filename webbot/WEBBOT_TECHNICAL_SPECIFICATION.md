## 项目概述

### 项目目标
WebBot是一个基于FileBot的文件到网页转换系统，允许用户上传各种文件（PDF、Word、图像、视频、音频）并自动转换为符合Canada.ca标准的网页。系统提供完整的版本控制、多语言支持和内容管理功能。

### 核心价值主张
1. **简单易用**: 用户直接上传文件，无需手动创建HTML内容
2. **成本效益**: 基于现有FileBot基础设施，减少重复开发
3. **合规性**: 遵循Canada.ca标准和WET-BOEW框架
4. **可扩展性**: 支持多种文件类型和业务需求扩展

### 技术栈选择

#### FileBot集成
- **紧密集成**: 方案A - 最大化利用FileBot现有能力

- **版本控制**: 使用FileBot的文档版本管理系统
- **存储共享**: 共享FileBot的文件存储基础设施

## 核心功能设计

### 1. 文件上传和处理

#### 支持的文件类型
- **文档**: PDF, Word (.doc, .docx)
- **图像**: JPG, PNG
- **视频**: 常见Web格式 (MP4, WebM)
- **音频**: 常见Web格式 (MP3, WAV, OGG)

#### 处理流程
```
用户上传文件 → WebBot接收 → 调用FileBot API → 
FileBot处理文件 → 返回文本/HTML内容 → 
WebBot存储内容 → 创建页面记录 → 返回页面预览
```

#### 内容提取策略
- **PDF/Word**: 完全文本提取，基础格式保留
- **图像**: 作为内嵌图片，可选OCR文本提取
- **视频/音频**: 作为媒体文件嵌入，元数据提取

### 2. 页面管理

#### 页面标识符生成
- **规则**: 标题 → 空格转"-" + 小写 + 法语字符转换
- **示例**: "À propos de nous" → "a-propos-de-nous"
- **重复处理**: 自动添加后缀 ("-2", "-3", ...)
- **URL结构**: `/{language_code}/{page_id}`

#### 页面状态生命周期
```
草稿 (draft) → 审核 (review) → 发布 (published) → 归档 (archived)
       ↑           ↓               ↓               ↑
       └───────────┴───────────────┴───────────────┘
              编辑/更新           取消发布
```

### 3. 版本控制 (方案A: 紧密FileBot集成)

#### 存储策略
- **当前版本**: 数据库文本字段存储 (`current_content_text`)
- **历史版本**: FileBot文件存储 (UUID命名)
- **源文件**: 用户上传的原始文件，存储在FileBot中
- **版本关系**: WebBot通过`webbot_page_versions`表管理FileBot文档引用

#### 版本创建策略
- **自动版本**: 每次发布创建正式历史版本
- **草案版本**: 重要编辑保存时创建草案版本
- **版本号**: 自动递增，保证连续性
- **变更描述**: 可选，记录版本变更内容

### 4. 多语言支持

#### 语言策略
- **主要语言**: 英语 (en) 和 法语 (fr) - Canada.ca官方语言
- **关联机制**: 通过`other_lang_page_id`字段关联不同语言版本
- **URL路由**: `/{language_code}/{page_id}`
- **语言切换**: 自动检测和手动切换选项

#### 翻译工作流
1. 创建英语页面
2. 标记需要翻译
3. 创建关联的法语页面
4. 内容翻译和校对
5. 同步发布

### 5. 引用管理 (全自动模式 - 对标Adobe系统)

#### 设计原则
- **全自动更新**: 页面移动时自动更新所有引用链接，无需人工干预
- **简洁通知**: 仅通知作者需要更改的页面数量，不显示详细列表
- **对标Adobe**: 参考当前Adobe系统的自动更新模式
- **最小干扰**: 为用户提供无缝、无干扰的操作体验

#### 引用类型
1. **内容链接 (content_link)**: HTML内容中的URL链接 (`<a href="/en/about-us">`)
2. **导航生成 (nav_generated)**: 基于`parent_id`自动生成的面包屑导航链接
3. **语言切换 (lang_switch)**: 基于`other_lang_page_id`自动生成的语言切换链接

#### 数据库设计
- **webbot_page_url_references**: 存储所有URL引用关系
- **webbot_url_redirects**: 存储页面重命名时的URL重定向
- **引用检测**: 页面保存/更新时自动提取和记录引用关系
- **引用追踪**: 基于URL路径追踪，不追踪数据库字段的直接引用

#### 页面移动流程
```
1. 用户请求页面重命名 (new_id)
2. 系统检测受影响页面 (调用check-move-impact)
3. 全自动更新所有引用链接 (无需用户确认)
4. 自动创建URL重定向 (301永久重定向)
5. 更新页面ID和URL
6. 返回结果: "已自动更新X个引用页面"
```

#### 技术实现
- **实时检测**: 页面保存时实时解析和记录引用关系
- **后台更新**: 引用更新在后台异步执行，不阻塞用户操作
- **错误处理**: 自动回滚机制，确保数据一致性
- **性能优化**: 引用表索引优化，支持快速查询

#### 用户界面设计
- **移动前检查**: 可选查看影响分析 (详细模式)
- **移动后通知**: 简洁的成功通知，仅显示更新数量
- **管理界面**: 引用关系查看和管理界面
- **重定向管理**: URL重定向的查看和管理

#### 扩展性考虑
- **后续改进**: 支持更复杂的引用分析报告
- **权限控制**: 基于用户角色的引用更新权限
- **批量操作**: 支持批量页面移动和引用更新
- **审计日志**: 引用更新的详细审计记录

### 6. 元数据管理

#### 核心元数据
- **SEO优化**: 标题、描述、关键词
- **社交媒体**: Open Graph标签、Twitter卡片
- **页面配置**: 模板选择、导航设置、权限控制
- **业务数据**: 分类标签、关联内容、自定义字段

#### 存储方式
- **结构化数据**: 存储在`webbot_page_metadata`表
- **扩展性**: 键值对结构支持任意扩展
- **类型支持**: 文本、JSON、URL、布尔值、数字

## 数据模型设计

### 核心实体关系
```
webbot_page (1) ──┐
    │            │
    ├── (1:N) ── webbot_page_metadata
    │            │
    ├── (1:N) ── webbot_page_versions ── (N:1) ── documents (FileBot)
    │            │
    └── (1:N) ── webbot_media_references ── (N:1) ── documents (FileBot)
```

### 关键字段设计原则
1. **id字段**: TEXT主键，基于标题生成，直接用于URL
2. **外键引用**: 所有引用使用TEXT类型，与FileBot保持一致
3. **软删除**: 使用`is_deleted`标志而非物理删除
4. **时间戳**: 创建时间、修改时间、发布时间分开记录
5. **状态管理**: 明确的状态机和生命周期
