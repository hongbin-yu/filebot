# FileBot 项目总结

## 项目概述
FileBot 是一个现代化的 Web 应用程序，用于文件管理和多格式文档统一转换为 PDF。系统替代旧的 smarti 系统，提供更好的用户体验和性能。

## 核心需求

### 1. 文件管理
- 层级结构：App → Drawer → Folder → Document → Page
- 文件操作：上传、下载、删除、重命名、移动、复制
- 批量操作支持
- 树状目录导航

### 2. 文档转换
- **输入格式**：TIFF, PDF, Word (.doc/.docx), JPEG, 文本打印流, PCL
- **输出格式**：统一 PDF
- **转换模式**：预处理转换（上传后立即转换）
- 批量转换支持
- 转换队列和进度跟踪

**关键设计变更**：从按需转换 → 预处理转换
- **旧系统**：按需转换（用户访问时才转换PDF，节省存储但延迟高）
- **新系统**：预处理转换（上传后立即转换，存储原始+PDF，用户体验优先）
- **理由**：存储成本大幅降低（10年前vs现在），用户体验成为首要考量

### 3. 用户管理
- 数据库管理的用户系统
- 角色和权限控制
- 多用户支持
- 用户数据隔离

### 4. 搜索功能（简化版）
- 基于文件名、元数据的搜索
- 页面级索引搜索（每个页面最多4个索引字段）
- **不包含**复杂的全文内容检索（旧系统此功能效果不佳）

### 5. 系统特性
- 响应式 Web 界面
- 现代用户体验
- 轻量级数据库（SQLite）
- 易于部署

## 技术架构

### 技术栈选择
- **前端**：React + TypeScript + Vite（现代、组件化、响应式）
- **后端**：Python FastAPI（快速开发、异步支持、文档处理生态丰富）
- **数据库**：SQLite（轻量级、易于部署、满足小型需求）
- **文件存储**：本地文件系统 + 配置路径

### 系统架构
```
前端 (React) ↔ 后端API (FastAPI) ↔ 转换引擎 ↔ 文件系统
                    ↓
               SQLite数据库
```

### 主要组件
1. **用户认证模块**：JWT令牌、密码哈希、权限检查
2. **文件管理模块**：层级数据结构、文件操作、元数据管理
3. **文档转换模块**：多格式转换、队列管理、错误处理
4. **搜索模块**：简化搜索基于索引和元数据
5. **管理界面**：用户友好的Web界面

## 数据结构设计

### 核心层级
```
App (应用)
  ├── Drawer (抽屉)
  │     ├── Folder (文件夹)
  │     │     ├── Document (文档)
  │     │     │     ├── Page (页面) - 最多4个索引
  │     │     │     └── ...
```

### 关键表结构
1. **users** - 用户信息、角色、权限
2. **apps** - 应用实例
3. **drawers** - 抽屉
4. **folders** - 文件夹（支持嵌套）
5. **documents** - 文档（存储文件信息、转换状态）
6. **pages** - 页面（包含最多4个索引字段）
7. **conversion_tasks** - 转换任务队列
8. **permissions** - 权限控制

## 搜索设计（简化版）

### 搜索维度
1. **文件名搜索**：文档原始文件名
2. **元数据搜索**：文件类型、大小、创建时间等
3. **索引搜索**：页面级别的索引字段（index1-index9，最多9个）
4. **层级搜索**：按App/Drawer/Folder路径筛选

### 不包含
- 复杂的全文内容检索（旧系统此功能效果不佳）
- OCR文本搜索（除非明确需要）
- 高级语义搜索

## 数据迁移设计

### 迁移策略
1. **并行运行**：新旧系统同时工作一段时间，逐步切换
2. **增量迁移**：定期同步新增和修改的数据
3. **兼容性设计**：新系统数据结构兼容旧系统，确保平滑迁移
4. **字段映射**：旧系统字段直接映射到新系统对应字段
5. **数据转换**：处理数据类型差异（如ID格式、时间格式）
6. **文件处理**：文件路径映射或文件复制

### 源数据库支持
旧系统使用多种数据库，迁移工具支持：
- **Oracle** - 生产环境主要数据库
- **MS SQL Server** - 生产环境常见
- **Sybase** - 生产环境常见
- **HSQLDB** - 开发/测试环境
- **MySQL** - 部分环境

### 关键调整
1. **页面索引扩展**：Page表支持9个索引字段（index1-index9）
2. **审计字段添加**：所有表添加 created_by, updated_by 字段
3. **文档字段扩展**：添加 document_number, title, status, type, comments 字段
4. **枚举值映射**：文档状态和类型使用兼容旧系统的枚举值

### 迁移工具
- **位置**：`migration/` 目录
- **功能**：多数据库 → SQLite 数据迁移
- **模式**：全量迁移 + 增量同步
- **支持**：断点续传、错误重试、进度监控
- **验证**：数据完整性检查、记录数对比

### 增量迁移方案
1. **定期同步**：每5分钟检查新数据
2. **状态跟踪**：记录最后同步ID/时间戳
3. **错误恢复**：失败后自动重试
4. **监控告警**：迁移异常时通知管理员

## 并行运行方案

### 新旧系统并行策略
1. **阶段一：只读并行**
   - 旧系统继续处理新数据
   - 新系统只读，用于测试和验证
   - 增量迁移工具持续同步数据

2. **阶段二：双向同步（可选）**
   - 新旧系统都可写入
   - 双向数据同步（复杂，需要冲突解决）
   - 或限制旧系统为只读，新系统处理新数据

3. **阶段三：完全切换**
   - 关闭旧系统写入
   - 最后一次全量迁移
   - 切换所有流量到新系统
   - 旧系统转为归档/备份

### 增量迁移实施
1. **初始全量迁移**：导入所有历史数据
2. **定期增量同步**：每5分钟同步新数据
3. **数据一致性检查**：定期验证新旧系统数据一致性
4. **切换准备**：确保新系统功能完整、性能达标

3. **并发转换**：需要任务队列管理

- 分块处理和进度报告
- 异步任务队列（Celery + Redis）
