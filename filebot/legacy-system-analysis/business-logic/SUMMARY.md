# 旧系统 (smarti) 业务逻辑分析

## 核心业务流程

### 1. 文档生命周期管理

#### 1.1 上传和导入流程
```
用户上传文件 → 文件验证 → 创建文档记录 → 
文件转换处理 → 页面提取 → 索引生成 → 完成
```

#### 1.2 转换处理流程
```
接收原始文件 → 识别文件类型 → 调用相应转换器 →
生成PDF → 提取页面 → 生成缩略图 → 存储结果
```

#### 1.3 查询和检索流程
```
用户输入搜索条件 → 构建查询 → 执行搜索 →
结果分页 → 显示页面列表 → PDF查看/下载
```

### 2. 核心服务组件

#### 2.1 文档转换服务 (SmartiPdfServiceManager)
**支持的转换类型**：
1. **img2pdf**：图像文件（TIFF, JPEG等）转PDF
2. **text2pdf**：文本文件转PDF
3. **pcl2pdf**：PCL打印流转PDF
4. **pdf2pdf**：PDF优化和重组
5. **afp2pdf**：AFP文件转PDF
6. **office2pdf**：Office文档（Word, Excel等）转PDF
7. **xml2pdf**：XML数据转PDF
8. **cold2pdf**：冷报告转PDF（特定业务格式）

**关键特性**：
- **按需转换模式**：只有当用户访问时才实时转换PDF（旧系统）
- 流式输出，支持大文件处理
- 页面级转换控制
- 支持批量转换（pages2pdf）
- 数据源提取（getDataSource）

**重要区别**：旧系统采用**按需转换**（on-demand conversion）模式，主要原因：
1. 10年前存储空间昂贵，无法存储所有文件的PDF版本
2. 转换是计算密集型，只在需要时执行
3. 原始文件存储，访问时实时转换并缓存

### 2.2 新旧系统转换模式对比

#### 旧系统：按需转换模式
**工作流程**：
```
用户上传文件 → 存储原始文件 → 等待用户访问 → 
用户请求查看 → 实时转换 → 返回PDF → 可选的临时缓存
```

**优点**：
- 节省存储空间（只存储原始文件）
- 避免不必要的转换计算

**缺点**：
- 用户首次访问延迟（需要等待转换）
- 重复访问可能重复转换（除非缓存）
- 高峰时段转换压力大

#### 新系统：预处理转换模式（现代方案）
**工作流程**：
```
用户上传文件 → 立即后台转换 → 存储原始文件+PDF版本 →
用户请求查看 → 直接返回预转换的PDF
```

**优点**：
- 用户无等待时间（PDF已预先转换）
- 更好的用户体验
- 转换负载分散（非高峰时段处理）
- 支持离线访问预转换文件

**缺点**：
- 需要更多存储空间（原始文件+PDF）
- 上传时处理时间增加

**技术可行性变化**：
1. **存储成本**：10年前昂贵 → 现在廉价
2. **计算能力**：10年前有限 → 现在强大
3. **用户体验期望**：10年前可接受等待 → 现在要求即时响应

#### 2.2 查询管理服务 (HibernateQueryManager)
**主要功能**：
- 复杂查询构建和执行
- 分页和排序处理
- 搜索结果缓存
- 权限过滤

#### 2.3 文件管理服务
**文件操作**：
- 文件上传和验证
- 文件存储和命名
- 文件版本管理
- 文件清理和归档

### 3. 业务规则和约束

#### 3.1 文件处理规则
1. **文件大小限制**：根据配置限制上传文件大小
2. **文件类型验证**：只允许特定格式文件上传
3. **病毒扫描**：可选的文件安全扫描
4. **重复文件检测**：基于内容哈希的重复检测

#### 3.2 转换规则
1. **转换优先级**：根据文件类型选择最佳转换器
2. **转换超时**：长时间运行的转换任务超时处理
3. **错误重试**：转换失败时的重试机制
4. **资源管理**：转换过程中的内存和CPU限制

#### 3.3 搜索规则
1. **权限过滤**：根据用户权限过滤搜索结果
2. **搜索范围**：支持App/Drawer/Folder层级搜索
3. **索引字段搜索**：支持9个索引字段的组合搜索
4. **文本搜索**：基于OCR文本的内容搜索

### 4. 用户权限和安全性

#### 4.1 认证机制
- **技术栈**：Acegi Security（Spring Security前身）
- **认证方式**：表单登录，记住我功能
- **会话管理**：HTTP会话，可配置超时

#### 4.2 权限模型
**角色层次**：
1. **管理员**：系统配置、用户管理、所有数据访问
2. **普通用户**：特定应用的数据访问和操作
3. **只读用户**：仅查看权限，无修改权限

**数据权限**：
- 应用级别权限控制
- 抽屉级别访问控制
- 文件夹级权限继承
- 文档级操作权限（读、写、删除）

#### 4.3 安全措施
1. **输入验证**：防止SQL注入和XSS攻击
2. **文件上传安全**：路径遍历防护，文件类型验证
3. **会话安全**：会话固定防护，CSRF防护
4. **审计日志**：所有关键操作日志记录

### 5. 错误处理和异常管理

#### 5.1 异常分类
1. **业务异常**：文件格式不支持，权限不足等
2. **系统异常**：数据库连接失败，文件系统错误等
3. **用户异常**：输入验证失败，操作冲突等

#### 5.2 错误处理策略
- **用户友好错误消息**：避免技术细节暴露
- **异常日志记录**：详细记录异常上下文
- **错误恢复**：自动重试，降级处理
- **监控告警**：关键错误实时告警

#### 5.3 错误页面
- **accessDenied.jsp**：权限拒绝页面
- **unknownException.jsp**：未知异常页面
- **错误消息显示**：在表单页面显示验证错误

### 11. 结论

旧系统的业务逻辑设计具有以下特点：
1. **完整的功能覆盖**：涵盖文档管理的全流程
2. **稳定的转换引擎**：支持多种格式的可靠转换
3. **灵活的配置能力**：支持不同企业的定制需求
4. **成熟的安全模型**：经过验证的权限和安全控制

**新系统设计原则**：
1. **兼容性优先**：确保业务流程的平滑过渡
2. **现代化改进**：在兼容基础上引入现代技术
3. **用户体验优化**：简化操作流程，提升效率
4. **扩展性增强**：为未来功能扩展预留接口

**迁移成功关键**：深入理解现有业务流程，确保新系统在功能、性能和用户体验上达到或超过旧系统水平。
